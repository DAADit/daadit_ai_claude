DAADit AI — Claude (Anthropic) Provider

Anthropic's Claude models as a first-class provider in Odoo 19 Enterprise's built-in AI.

What this module does

Adds Anthropic's Claude models — Opus, Sonnet, and Haiku — as an LLM provider for the standard Odoo 19 Enterprise ai module. Your AI agents, chatbots, and Discuss integrations can now dispatch chat and tool calls directly to api.anthropic.com using your own Anthropic account. Existing topic configurations, tool actions, and RAG sources keep working — this module plugs in as an additional provider option, not a replacement.

Key features

🤖 Full Claude model lineup

Adds Claude Opus, Claude Sonnet, and Claude Haiku (4.5 & 4.6/4.7 families) to the ai.agent LLM Model dropdown. Requests go to Anthropic's /v1/messages endpoint using your key from console.anthropic.com.

🛠 Tool calling with proper schemas

All ten standard Odoo AI tools (Search, Read Group, Get Fields, Open Menu *) are exposed to Claude with typed JSON Schema definitions. Multi-turn tool_use → tool_result loops run automatically until Claude returns a final text response or a 6-iteration safety cap is hit.

🛡️ Per-agent access control

Allowed-models and blocked-models lists on every agent constrain which Odoo models Claude can query via tools. One-click presets fill in curated business-model / sensitive-system-model lists so admins don't have to type technical names.

🔒 Field-level PII blocklist

Configure model.field entries that must never leave the agent. Matches are scrubbed from tool results and filter/groupby/aggregate clauses referencing them are rejected — so an LLM can't binary-search a value through the query.

📊 Usage tracking & cost estimation

Every chat call writes a row to daadit_ai_claude.usage with token counts, iteration count, tool-usage flag, and an estimated USD cost per Anthropic's public price list. Pricing is overridable via ir.config_parameter when Anthropic updates their rates.

⚖️ GDPR-ready erase button

Partner form gains an Erase Claude usage (GDPR) button that anonymises the user link on all usage rows tied to that partner's internal users — token counts and cost figures kept for aggregate reporting.

🌐 URL allowlist for the API key

The base URL is validated against a strict allowlist before any request is sent, so a tampered ir.config_parameter row cannot exfiltrate your API key to an untrusted host.

🗣️ Language mirroring

The dispatch layer appends a language-mirror instruction to the system prompt so smaller Claude models reliably reply in the user's language (Dutch, French, German, …) even when the agent's system prompt is in English.

How it fits together

When an AI agent is configured with a Claude model, its chat calls take a different path than the OpenAI/Gemini defaults:

  • Chat — routes to POST /v1/messages on api.anthropic.com with your key.
  • Tool calls — converted to Anthropic's input_schema envelope; results echoed back as tool_result content blocks.
  • Embeddings — Anthropic does not offer an embeddings API. The module deflects the embedding-model lookup to text-embedding-3-small so RAG/Sources keep working through the OpenAI/IAP path that stock Odoo already uses. Chat runs on Claude, embeddings run on whichever provider you have configured for them.

Set-up in 5 steps

  1. Install this module from the Apps screen.
  2. Open Settings → General Settings → AI.
  3. Toggle Use your own Anthropic Claude account on and paste your API key from console.anthropic.com/settings/keys (keys start with sk-ant-).
  4. Save.
  5. Open any AI Agent, pick a Claude model (e.g. Sonnet 4.6 as a balanced default), and try a prompt.

Existing agents on other providers keep working unchanged.

Requirements

  • Odoo 19 Enterprise — depends on the stock ai and ai_app modules.
  • An Anthropic account with billing set up at console.anthropic.com (Anthropic bills you directly for chat token usage; this module only routes the call).
  • Python's requests library (already present in any standard Odoo install).
  • Outbound HTTPS to api.anthropic.com from the Odoo server.
